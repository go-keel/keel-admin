# Project structure: kernel and business area

Read this before adding a file, to know whether its directory is kernel (read-only), business or an append-only seam.

## 2. Project structure

Legend: **▣ = kernel, read-only**; **★ = business writes**; **☆ = half-open** (append only, do not change).

```
<repo>/
├── cmd/<app>/
│   ├── main.go                    # ▣ startup skeleton
│   ├── di.go                      # ☆ assembly seam: permission registration + data→biz→service wiring
│   └── registration_test.go       # ☆ seals di.go's registerPermissions; no change when adding a module
│
├── api/<pkg>/v1/
│   ├── auth.proto user.proto role.proto dept.proto audit.proto meta.proto   # ▣ sys domain contracts
│   ├── types.proto                # ☆ shared messages (NamedRef etc.; upstream gives the baseline, derived repos append)
│   ├── <domain>.proto             # ★ business proto (business modules add their own here)
│   └── *.pb.go                    # generated by make proto
│
├── internal/
│   ├── core/                      # ▣▣▣ the only kernel directory ▣▣▣
│   │   ├── perm/                  # types, MustRegister/Seal, Set/Effective, startup checks,
│   │   │                          #   proto anonymous set, Principal ctx
│   │   ├── permdata/              # ApplyScope GORM helper
│   │   ├── middleware/            # principal / authz / audit
│   │   ├── captcha/               # Provider interface + registry (built-in base64, otp.md §7.4)
│   │   ├── sys/                   # system domain (split into biz/data/service packages)
│   │   │   ├── biz/               #   auth, user, role, dept, arbac, scope, otp, audit, errors
│   │   │   ├── data/              #   sys_* GORM models, repos (no seeding in code)
│   │   │   ├── service/           #   transport adapters + perm.go (sys permission codes/bindings, same registration)
│   │   │   └── totp/              #   TOTP algorithm + AES-GCM secret (RFC 6238)
│   │   └── data/                  # Data struct (the admin database handle)
│   │
│   ├── biz/                       # ★ business biz layer (layout: one file per domain, transport-agnostic)
│   │   ├── <domain>.go            #   DO + Repo interface + UseCase + code constants/Perms metadata
│   │   └── errors.go              #   business sentinel errors
│   ├── data/                      # ★ business data layer
│   │   ├── model.go               #   business GORM models (up to 5 here; split by domain beyond that)
│   │   └── <domain>.go            #   Repo implementations, queries use ApplyScope
│   ├── service/                   # ★ business service layer
│   │   ├── <domain>.go            #   transport adapter
│   │   ├── <domain>_perm.go       #   permission code + endpoint binding declarations (operation constants usable here)
│   │   └── http.go                #   HTTP registration functions of the business services (di.go appends them)
│   ├── conf/                      # ☆ half-open: business fields in app.proto/Bootstrap
│   ├── server/                    # ▣ HTTP registration, SPA/brand mounting, providers
│   └── i18n/                      # ▣ bundle.go, sys.en.toml, sys.zh-CN.toml (kernel copy;
│                                  #   the overwrite covers only these three files)
│                                  # ☆ app.*.toml (business copy) and sys.<other language>.toml
│                                  #   translated by the derived repo: upstream touches neither
│
├── migrations/                    # ▣ hand-written .sql, MySQL dialect (no AutoMigrate)
│   ├── admin/0_schema.sql              # ▣ sys tables + root seed (see root in README.md §3)
│   └── business/0_schema.sql           # ★ business tables (plus baseline and incremental scripts once in production)
│
├── web/src/
│   ├── lib/ components/ hooks/    # ▣ permission checks, request layer, shared pieces (kernel; except components/ui/)
│   ├── shell.ts nav.ts styles/    # ☆ shell switches, menu list, appearance presets (assembly seams)
│   ├── languages.ts timezones.ts  # ☆ language and time zone registries (assembly seams)
│   ├── header.tsx login-layout.tsx # ☆ the two header slots, login page layout (assembly seams)
│   ├── generated/                 # generated by make proto, never edited by hand
│   ├── routes/_app/sys/           # ▣ kernel management pages
│   └── routes/_app/<domain>/      # ★ business pages (outside sys/)
│
├── configs/                       # config.yaml (infrastructure) + app.yaml (sys: section + business config, deployment-and-config.md §13)
├── docs/                          # guides/ practices/ admin/ (this page is in admin/) adr/
├── scripts/ Makefile AGENTS.md openapi.yaml
```

`core/sys/biz` and the business `internal/biz` share a name but are different packages; di.go imports the business area
as `nbiz` / `ndata` / `nsvc` (`docs/admin/assembly.md`).
